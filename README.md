# Personal Assistant

Консольний застосунок «Персональний помічник»: контакти, нотатки, задачі, робота
з файлами, імпорт/експорт, AI-підказки та зовнішні API.

## Швидкий старт

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/pa            # або: .venv/bin/python -m personal_assistant
```

## Структура

```
src/personal_assistant/
├── core/       спільний фундамент: конфіг, помилки, JSON-сховище, репозиторій
├── features/   вертикальні зрізи — кожна фіча самодостатня
│   ├── contacts/  notes/  tasks/  files/  ai/  external/
└── cli/        REPL, реєстр команд, автодоповнення, fuzzy-підказки
```

Кожна фіча складається з `models.py` (дані + валідація), `service.py`
(бізнес-логіка) і `commands.py` (реєстрація CLI-команд). `cli/` **не імпортує**
фічі напряму — вони реєструють себе самі через `register(registry)`. Завдяки
цьому будь-яку теку з `features/` можна винести в окремий репозиторій разом з її
тестами, не чіпаючи решту коду.

## Команди застосунку

Повний перелік — `help`, довідка по одній команді — `help <команда>`.
Готові розділи:

| Команда | Що робить |
|---|---|
| `add contact <ім'я> [телефон]` | Створити контакт |
| `list contacts` · `contacts` | Усі контакти (обрані вгорі) |
| `show contact <контакт>` | Картка контакту |
| `find <запит>` | Пошук за іменем, номером, email, адресою |
| `add phone` · `remove phone` | Номери телефонів |
| `set email` · `set address` · `set birthday` | Решта полів |
| `rename contact` · `delete contact` | Перейменувати, видалити |
| `birthdays [днів]` | Хто святкує найближчими днями |
| `favorite` · `unfavorite` · `list favorites` | Обрані контакти |

Email перевіряється не лише на формат: поштові домени держав-агресорів
відхиляються — зони РФ (`.ru`, `.su`, `.moscow`, `.tatar`, `.рф`, `.москва`,
`.рус`, `.дети`), зони Білорусі (`.by`, `.бел`) разом із їх punycode-формами,
та сервіси РФ у чужих зонах (`yandex.com`, `vk.com` тощо). Перелік — у
`features/contacts/blocked_domains.py`, правило працює за суфіксом, тож
піддомени закриваються автоматично.

| `add note <заголовок> [текст]` | Створити нотатку |
| `list notes` · `notes` | Усі нотатки, найсвіжіші згори |
| `show note <нотатка>` | Нотатка повністю |
| `edit note` · `rename note` · `delete note` | Змінити, перейменувати, видалити |
| `find notes <запит>` | Пошук за заголовком, текстом і тегами |
| `add tag` · `remove tag` | Теги нотатки |
| `notes by tag <тег>` | Нотатки з тегом |
| `sort notes` | Нотатки, згруповані за тегами |
| `list tags` · `tags` | Усі теги з кількістю |

| `add task <заголовок> [опис]` | Створити задачу |
| `list tasks [статус]` · `tasks` | Задачі, за потреби лише одного статусу |
| `show task <задача>` | Задача повністю |
| `edit task` · `rename task` · `delete task` | Змінити, перейменувати, видалити |
| `find tasks <запит>` | Пошук за заголовком і описом |
| `set status <задача> <статус>` | `new` · `in_progress` · `done` · `cancelled` |
| `start` · `done` · `cancel` | Скорочення для зміни статусу |
| `set due <задача> [дата]` | Дедлайн (порожнє значення очищає) |
| `overdue` | Задачі з простроченим дедлайном |

Статус приймається і канонічним значенням з ТЗ (`in_progress`), і українським
відповідником (`в роботі`) — тим самим, який видно в таблиці. У сховищі
завжди лежить канонічне значення.

Список задач упорядковано під питання «чим зайнятись зараз»: спершу незакриті,
всередині — за дедлайном, задачі без дедлайну в кінці своєї групи. Прострочені
позначені `!`.

| `sort files <тека>` | Як розклалися б файли за категоріями |
| `normalize names <тека>` | Які імена змінилися б після транслітерації |
| `find duplicates <тека>` | Файли з однаковим вмістом (SHA-256) |

**Команди роботи з файлами нічого не змінюють на диску.** Вони показують
попередній перегляд; застосування плану буде окремим кроком. Пропускаються
приховані файли, символьні посилання на теки та теки категорій у корені —
останні є результатом попереднього сортування.

Колізії імен розв'язуються числовим суфіксом (`zvit.txt`, `zvit_2.txt`) і
позначаються в плані знаком `⚠`. Порівняння регістронезалежне: на macOS і
Windows `Fail.txt` та `fail.txt` — це один файл, тож план не має залежати від
системи.

| `export contacts <файл> [force]` | Зберегти контакти у `.json` або `.csv` |
| `import contacts <файл> [режим]` | Прочитати контакти з `.json` або `.csv` |

Формат обміну навмисно відрізняється від сховища: без ідентифікаторів і
службових дат, дати у форматі `DD.MM.YYYY`. Це файл для обміну й ручного
редагування, **а не резервна копія** — нею є сам `data/contacts.json`.

CSV пишеться з BOM і `CRLF`, щоб Excel одразу показував кирилицю. На читанні
роздільник визначається автоматично, тож файл, збережений українським Excel
через `;`, імпортується без правок.

Режими імпорту для контакту, який уже є в книзі (зіставлення за іменем):

| Режим | Що робить |
|---|---|
| `skip` (типовий) | Лишає наявний запис недоторканим |
| `replace` | Замінює всі поля, зберігаючи ідентифікатор |
| `merge` | Об'єднує телефони й заповнює лише порожні поля |

Помилковий рядок не перериває імпорт — він потрапляє у звіт із номером рядка,
решта файлу застосовується. Експорт не перезаписує наявний файл без слова
`force`.

Запис можна вказати текстом, його частиною або коротким ідентифікатором:
`show contact Петренко`, `show note 08b53906`. Значення з пробілами беруться
в лапки: `add contact "Іван Петренко"`, `add tag Зустріч "Робочі Справи"`.

Теги нормалізуються: `#Робочі Справи`, `robochi_spravy` і `#РОБОТА` не
перетворюються на кілька різних тегів. Заголовки нотаток, на відміну від імен
контактів, повторюватись можуть — тоді запис адресується ідентифікатором.

## Інтерфейс

`Tab` доповнює не лише назви команд, а й аргументи — імена контактів,
заголовки нотаток і задач, теги, статуси, режими імпорту та шляхи. Значення з
пробілами вставляються вже в лапках. Список варіантів залежить від контексту:
`remove phone Іван <Tab>` показує номери саме Івана, `remove tag Зустріч
<Tab>` — теги саме цієї нотатки.

Нижній рядок показує сигнатуру поточної команди й підсвічує, який аргумент
вводиться зараз. `↑`/`↓` гортають історію, а раніше введені рядки
підказуються сірим текстом.

Помилка в назві не потребує довідки: `shw contact Іван` відповість
«Можливо, ви мали на увазі: show contact, list contacts, contacts?».

## Конфігурація

Змінні читаються з оточення або з `.env` (див. `.env.example`).

| Змінна | Призначення | Типове значення |
|---|---|---|
| `PA_DATA_DIR` | Куди складати JSON-файли даних | `./data` |
| `ANTHROPIC_API_KEY` | Ключ для AI-функцій | не заданий → офлайн-режим |

Якщо ключа немає, AI-команди працюють на локальних евристиках — застосунок
залишається повністю робочим.
